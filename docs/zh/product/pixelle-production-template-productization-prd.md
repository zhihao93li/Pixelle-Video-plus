版本：v0.1
日期：2026-06-30
状态：讨论稿
适用范围：Pixelle 视频生成 UI、生产模板、项目默认设置、生成历史、Ops/Codex 生成闭环
目标读者：产品、前端、后端、Ops/Codex 执行者
关联文档：

1. `docs/zh/product/pixelle-video-generation-pipeline-prd.md`
2. `docs/zh/product/pixelle-montage-capability-integration-prd.md`

## 1. 一句话目标

把已经沉淀到后端的“生产模板”变成用户能看见、能理解、能复用的产品能力：用户日常生成时不选择 provider，不理解 runtime，只选择或使用项目默认生产线；OpenMontage 的 montage、素材清单、质检、合成增强等能力通过生产模板逐步融入 Pixelle。

## 2. 背景和当前问题

当前分支已经完成了一部分后端基础：

1. 视频生成有了生产模板定义。
2. 项目可以保存默认生成设置。
3. Ops/Codex 可以按项目默认模板请求生成。
4. 生成结果可以带上模板、合成方式、质检、素材清单等摘要。
5. 已经预置了日常短视频、高质量解释、素材增强、真实素材混剪等模板方向。

但是用户在 UI 上仍然很难感知变化。

核心原因：

1. 默认生成页仍然像原来的“输入内容 -> 生成视频”。
2. 生产模板只在局部模式中出现，没有成为生成主流程的一部分。
3. 用户看不到“当前项目默认生产线是什么”。
4. 用户看不到“这条视频用了哪个生产模板、哪些素材、质检是否通过”。
5. OpenMontage 能力仍像后端配置，而不是清晰的视频生成方式。

因此，本 PRD 要解决的不是“继续增加更多底层工具”，而是：

```text
让生产模板成为 Pixelle 视频生成的产品入口。
```

## 3. 产品原则

### 3.1 不让用户每次选择 provider

普通用户日常生成时不应该看到：

1. TTS provider。
2. 图片或视频生成 provider。
3. ComfyUI workflow。
4. HyperFrames、Remotion、HTML+FFmpeg 等 runtime。
5. 各种底层参数。

这些应该固定在生产模板里。

用户只需要理解：

```text
我要用哪条生产线做这条内容？
```

默认情况下，连这一步也不需要每次选择，系统直接使用项目默认生产模板。

### 3.2 OpenMontage 不直接等于 pipeline

OpenMontage 的价值不是“把它的每个 pipeline 搬进 Pixelle”，而是把其中高性价比能力融入 Pixelle 的生产模板体系。

映射关系应该是：

```text
OpenMontage 能力
  -> Pixelle 工具能力 / 合成能力 / 质检能力 / 素材能力
  -> 被固定进生产模板
  -> 由 Pixelle pipeline 执行
```

因此，montage 生成方式不直接等于一个 Pixelle pipeline。它更适合先表现为几个产品化生产模板：

1. 素材增强视频。
2. 真实素材混剪视频。
3. 高质量动效解释视频。

只有当某类视频的执行逻辑和输入输出明显不同，才需要新增真正的 pipeline。

### 3.3 短期不做大规模重构

短期目标是把已经做好的能力产品化，而不是重写视频生成架构。

本阶段优先：

1. 让用户看见生产模板。
2. 让项目默认模板真正生效。
3. 让生成结果可解释。
4. 让素材和 montage 能力以轻量方式进入主流程。

不优先：

1. 重写 Streamlit。
2. 重写 pipeline class。
3. 引入完整 OpenMontage agent-first 执行框架。
4. 同时接入多套新合成 runtime。
5. 做复杂模板编辑器或模板市场。

## 4. 核心概念定义

### 4.1 Pipeline

Pipeline 是底层视频生产流程类型，回答：

```text
这类视频从输入到输出怎么生产？
```

它是系统能力，不是普通用户每天都要选择的产品项。

### 4.2 生产模板

生产模板是 pipeline 的固定配置实例，回答：

```text
这条固定生产线每一步具体怎么做？
```

生产模板固定：

1. 使用哪个 pipeline。
2. 支持什么输入。
3. 默认声音和音频策略。
4. 默认画面生成或素材使用策略。
5. 默认合成方式。
6. 字幕、BGM、画幅、时长规则。
7. 质量检查规则。
8. 是否需要用户素材。
9. 失败时如何提示。

用户日常看到的是生产模板，不是 provider。

### 4.3 项目默认生产模板

项目默认生产模板是某个项目的常用生产线。

例如：

```text
PetWoods 小红书项目
默认生产模板：小红书日常短视频
```

用户在该项目中输入新内容时，系统默认使用这条生产线。

只有当用户明确要做“高质量解释视频”或“真实素材混剪”时，才切换模板。

### 4.4 生成方式

生成方式是用户能理解的视频形态。

第一批建议展示：

| 生成方式 | 用户理解 | 背后模板 |
|---|---|---|
| 日常短视频 | 稳定、快速、适合常规更新 | 小红书日常短视频模板 |
| 高质量解释视频 | 更强动效、适合重点内容 | 高质量解释模板 |
| 素材增强视频 | 使用已有图片或视频包装成片 | 素材增强模板 |
| 真实素材混剪 | 更像真实 footage montage | 真实素材混剪模板 |

生成方式是产品文案；生产模板是可版本化配置；pipeline 是底层执行能力。

## 5. 用户场景

### 5.1 日常稳定生成

用户目标：

```text
我每天给账号做一条视频，希望输入内容后稳定生成，不想配置工具。
```

产品体验：

1. 用户进入生成页。
2. 系统显示当前项目默认生产线：日常短视频。
3. 用户输入选题、文案或已确认内容。
4. 点击生成。
5. 系统按默认模板完成视频。
6. 结果页显示成片、模板、质检状态和素材摘要。

### 5.2 重点内容强化表现

用户目标：

```text
这条内容更重要，我希望视频看起来比日常模板更好。
```

产品体验：

1. 用户在生成页切换为高质量解释视频。
2. 系统提示耗时更长、视觉表现更强。
3. 用户不需要选择 HyperFrames 或 Remotion。
4. 生成失败时，系统说明是合成失败、素材失败还是配置缺失。

### 5.3 使用已有素材做视频

用户目标：

```text
我已经有一些图片或视频，希望系统帮我组织成一条短视频。
```

产品体验：

1. 用户选择素材增强视频。
2. 上传或选择图片、视频、商品图、宠物素材。
3. 系统生成剪辑计划、字幕、配音和成片。
4. 结果页展示每个素材被用在哪里。

### 5.4 真实素材混剪

用户目标：

```text
我希望视频更像真实 footage montage，而不是纯 AI 图片拼接。
```

产品体验：

1. 用户选择真实素材混剪。
2. 第一阶段优先使用用户上传素材。
3. 系统按镜头组织真实素材、字幕、BGM 和转场。
4. 用户能看到素材来源和使用位置。

## 6. 产品改造范围

### 6.1 生成首页

当前问题：

1. 默认生成页没有明显变化。
2. 用户不知道当前使用哪个生产模板。
3. 生产模板选择不在主流程中。

改造目标：

1. 在生成页主操作区展示“当前生产线”。
2. 默认显示项目默认生产模板。
3. 支持用户主动切换生成方式。
4. 普通模式不展示 provider、runtime、workflow。

建议信息结构：

```text
当前生产线
  日常短视频
  适合：日常更新、稳定快速、自动生成字幕和配音
  预计耗时：约 X 分钟
  质量策略：基础质检
  [更换生产线]
```

更换生产线时展示卡片：

1. 日常短视频。
2. 高质量解释视频。
3. 素材增强视频。
4. 真实素材混剪。

每张卡片展示：

1. 名称。
2. 适用场景。
3. 需要输入什么。
4. 是否需要素材。
5. 预计耗时。
6. 当前是否可用。

### 6.2 项目设置

当前问题：

1. 项目默认生产模板已经有后端基础，但没有产品入口。
2. 用户无法明确知道项目默认生产线。

改造目标：

1. 项目设置中增加“默认生产线”。
2. 用户可以为项目选择默认生产模板。
3. 默认设置保存后，后续生成自动使用。

设置项：

| 设置项 | 说明 |
|---|---|
| 默认生产模板 | 项目日常生成默认使用的模板 |
| 可用生产模板 | 当前项目允许使用哪些模板 |
| 高级能力状态 | 哪些模板因为配置缺失不可用 |
| 默认质量策略 | 基础、严格，第一阶段可以只读 |

验收上，用户刷新页面后默认生产线仍保持一致。

### 6.3 生成任务提交

产品规则：

1. 如果用户没有选择模板，使用项目默认生产模板。
2. 如果项目没有默认模板，使用系统推荐默认模板。
3. 如果用户主动切换模板，本次生成使用切换后的模板。
4. 如果模板不可用，不允许伪装成功。
5. 如果模板缺少必要输入，先提示用户补充，而不是进入失败任务。

用户不应该看到：

```text
请选择 provider
请选择 workflow
请选择 compose runtime
```

用户应该看到：

```text
这个生产线需要上传至少 1 个素材
这个生产线当前不可用，因为缺少视频合成配置
这个生产线耗时更长，适合重点内容
```

### 6.4 生成历史和结果详情

当前问题：

1. 用户只看到生成结果，很难知道生成质量和使用方式。
2. OpenMontage 的质检和素材追踪价值没有体现出来。

改造目标：

1. 每条生成结果显示使用的生产模板。
2. 显示质量检查状态。
3. 显示素材清单摘要。
4. 失败时显示失败层和可理解原因。

历史列表建议展示：

| 字段 | 说明 |
|---|---|
| 视频标题/内容摘要 | 用户识别任务 |
| 生产模板 | 日常短视频、高质量解释、素材增强、真实素材混剪 |
| 状态 | 生成中、成功、失败、质检警告 |
| 质量 | 通过、警告、失败 |
| 时间 | 创建时间和完成时间 |

详情页建议展示：

1. 成片预览。
2. 生产模板。
3. 输入摘要。
4. 质量检查结果。
5. 素材清单。
6. 失败原因。
7. 可执行下一步：重新生成、换模板重试、进入发布、返回编辑。

### 6.5 Ops/Codex 入口

当前方向正确：Ops/Codex 不应该每次问用户 provider。

产品规则：

1. 默认使用项目默认生产模板。
2. 只有当用户说“做高质量版”“用素材混剪”“做真实素材风格”时，才切换模板。
3. 如果模板不可用，Ops/Codex 应说明不可用原因和可选替代。
4. 请求生成后，Ops/Codex 需要展示真实任务状态，而不是只说已请求。

示例：

```text
用户：这条做高质量一点
系统：将使用「高质量解释视频」生产线。该生产线耗时更长，会使用严格质检。
```

## 7. 阶段规划

### Phase 1：让生产模板在生成页可见

优先级：P0

目标：

1. 用户进入生成页就能看到当前生产线。
2. 默认生成流程仍然简单。
3. 用户不需要每次选择 provider。

范围：

1. 生成页增加当前生产线模块。
2. 支持从可用模板中切换生成方式。
3. 普通模式隐藏 provider、runtime、workflow。
4. 模板展示使用产品语言，而不是技术语言。

验收标准：

1. 用户打开生成页时，可以看到“当前生产线”。
2. 默认显示项目默认模板或系统默认模板。
3. 点击生成时，即使用户不切换模板，也会按默认模板生成。
4. 用户可以切换到高质量解释、素材增强、真实素材混剪等模板。
5. 不显示 provider 选择。
6. 不显示 HyperFrames、Remotion、HTML+FFmpeg 等技术名，除非进入高级详情。
7. 模板不可用时显示明确原因，并阻止提交。

暂不做：

1. 不做复杂模板编辑器。
2. 不做模板市场。
3. 不允许用户自由组合每一步 provider。

### Phase 2：项目默认生产线设置

优先级：P1

目标：

1. 项目可以保存默认生产模板。
2. 后续生成自动使用该默认模板。
3. 设置对 UI、Ops/Codex、API 一致生效。

范围：

1. 项目设置页增加默认生产线。
2. 生成页读取项目默认设置。
3. Ops/Codex 读取项目默认设置。
4. 模板可用性检查前置。

验收标准：

1. 用户可以在项目设置中选择默认生产线。
2. 保存后刷新页面，默认生产线保持不变。
3. 从 UI 生成和从 Ops/Codex 生成使用同一个项目默认模板。
4. 如果默认模板变为不可用，生成页明确提示，并提供切换入口。
5. 如果项目没有设置默认模板，系统使用安全默认值。
6. 不出现“UI 一个默认、Ops 另一个默认”的情况。

暂不做：

1. 不做多账号复杂继承规则。
2. 不做按内容类型自动推荐模板。
3. 不做非技术用户编辑模板底层参数。

### Phase 3：生成结果可解释

优先级：P2

目标：

1. 用户知道每条视频是怎么生成的。
2. 用户知道视频是否可发布。
3. OpenMontage 的质检和素材清单价值在产品上可见。

范围：

1. 历史列表展示生产模板和质量状态。
2. 任务详情展示质检摘要。
3. 任务详情展示素材清单摘要。
4. 失败时展示失败层和用户可理解原因。
5. Ops asset check 使用相同的质量结果。

验收标准：

1. 新生成视频的历史详情能看到生产模板名称和版本。
2. 历史详情能看到成片质量：通过、警告、失败。
3. 至少展示最终视频、旁白音频、主要画面素材、BGM 或字幕中的关键素材。
4. 质检失败的视频不能被包装成可发布成功。
5. 失败原因能区分输入缺失、配置缺失、生成失败、合成失败、质检失败。
6. Ops/Codex 查询同一任务时看到一致摘要。

暂不做：

1. 不做完整资产库。
2. 不做跨任务素材复用管理。
3. 不做复杂视觉评分。

### Phase 4：素材增强与真实素材混剪 MVP

优先级：P3

目标：

1. 把 OpenMontage 的素材驱动和 montage 思路变成可用的 Pixelle 生成方式。
2. 第一版以用户素材为主，降低素材检索和版权复杂度。
3. 结果仍进入同一套历史、质检和 Ops 闭环。

范围：

1. 素材增强视频支持上传或选择图片、视频。
2. 真实素材混剪支持至少一组用户素材输入。
3. 系统生成轻量剪辑计划。
4. 成片通过统一合成和质检。
5. 结果记录素材来源和使用位置。

验收标准：

1. 用户可以选择素材增强视频模板并提交素材。
2. 用户可以选择真实素材混剪模板并提交素材。
3. 系统在提交前校验素材数量、类型和可用性。
4. 生成结果包含素材清单。
5. 生成结果能播放，并通过基础质检。
6. 如果素材不足或格式不支持，系统在生成前提示。
7. 不使用 mock 素材冒充真实素材。

暂不做：

1. 不做完整 stock/archive 素材搜索。
2. 不做复杂语义检索。
3. 不做长视频自动拆条。
4. 不做专业剪辑时间线编辑器。

### Phase 5：高质量合成 runtime 试点

优先级：P4

目标：

1. 为高质量解释视频模板接入更强表现力的合成方式。
2. 不影响日常短视频稳定性。
3. 只通过生产模板暴露，不让用户选择 runtime。

范围：

1. 选择 HyperFrames 或 Remotion 做一个试点。
2. 高质量解释模板使用新合成方式。
3. 日常短视频继续使用稳定默认方式。
4. 新 runtime 失败时返回明确错误，不静默降级。

验收标准：

1. 日常短视频模板不受影响。
2. 高质量解释模板的视觉表现与日常模板有明显差异。
3. 新合成方式失败时，任务状态真实失败。
4. 失败原因能说明是合成环境、素材输入、渲染过程还是输出质检问题。
5. 成片仍进入统一历史、质检和 Ops 闭环。

暂不做：

1. 不同时接入 HyperFrames 和 Remotion。
2. 不做用户自定义动效编辑器。
3. 不把 runtime 名称暴露给普通用户。

## 8. 第一批生产模板建议

### 8.1 日常短视频

定位：

```text
默认、稳定、适合日更。
```

输入：

1. 选题。
2. 文案。
3. 已审核分镜。

产品行为：

1. 如果只有选题，系统先生成文案或分镜。
2. 如果已有文案，系统尊重文案，不重写。
3. 如果已有分镜，系统直接进入配音、画面和合成。

验收重点：

1. 生成稳定。
2. 失败原因清晰。
3. 不要求用户选择工具。

### 8.2 高质量解释视频

定位：

```text
重点内容、强动效、更高质量。
```

输入：

1. 主题。
2. 完整文案。
3. 分镜结构。

产品行为：

1. 模板说明中提示耗时更长。
2. 质检策略更严格。
3. 可在后续阶段接入 HyperFrames 或 Remotion。

验收重点：

1. 和日常模板在结果上有明显差异。
2. 失败不影响日常模板。

### 8.3 素材增强视频

定位：

```text
用户已有素材，系统负责包装成片。
```

输入：

1. 图片。
2. 短视频。
3. 商品图或宠物素材。
4. 可选文案或卖点。

产品行为：

1. 先校验素材是否可用。
2. 生成轻量剪辑计划。
3. 产出视频和素材清单。

验收重点：

1. 素材来源可追踪。
2. 素材不足时不进入假成功。

### 8.4 真实素材混剪

定位：

```text
更像真实 footage montage 的视频。
```

输入：

1. 用户上传素材。
2. 可选主题或文案。
3. 可选风格要求。

产品行为：

1. 第一版优先使用用户素材。
2. 生成镜头顺序、字幕和转场。
3. 保留素材来源记录。

验收重点：

1. 不是单纯 AI 图像拼接。
2. 用户能看见使用了哪些真实素材。

## 9. 与现有实现的关系

当前已经具备的基础：

1. 后端已有生产模板注册和编译能力。
2. 项目默认生成设置已有存储基础。
3. Ops/Codex 已能使用项目默认模板。
4. 生成结果摘要已有后端结构。
5. 已经有日常、高质量、素材增强、真实素材混剪的模板雏形。

仍需补齐的产品化能力：

1. 生成页主流程展示生产模板。
2. 项目设置页管理默认生产模板。
3. 模板可用性和输入要求前置展示。
4. 历史列表和详情展示生成摘要。
5. 素材上传/选择入口。
6. 真实素材混剪的最小可用体验。
7. 高质量 runtime 的稳定试点。

结论：

```text
短期不是缺少“更多 pipeline”。
短期缺少的是“把已有生产模板变成用户能感知和复用的产品入口”。
```

## 10. 关键验收总标准

本 PRD 完成后，应该满足：

1. 用户能在生成页看到当前生产线。
2. 用户可以不选 provider 直接生成。
3. 项目可以设置默认生产线。
4. UI、Ops/Codex、API 使用同一套默认模板逻辑。
5. 每条生成结果能看到使用的生产模板。
6. 每条生成结果能看到质量状态。
7. 素材增强和真实素材混剪有明确入口。
8. 模板不可用时系统保持诚实失败，不包装成成功。
9. OpenMontage 能力以生产模板和能力层形式融入，而不是照搬其 agent-first 制作系统。

## 11. 指标

产品指标：

1. 默认模板生成占比。
2. 用户主动切换模板占比。
3. 首次生成成功率。
4. 生成失败原因可理解率。
5. 质检失败拦截次数。
6. 素材增强模板使用率。
7. 真实素材混剪模板使用率。

体验指标：

1. 用户从进入生成页到点击生成的时间。
2. 用户是否能说清当前用了哪条生产线。
3. 用户是否还需要询问 provider 怎么选。
4. 生成失败后用户是否知道下一步该怎么处理。

## 12. 决策和开放问题

### 12.1 已确认方向

1. 不让用户每次选择 provider。
2. pipeline 定义保留现有体系。
3. OpenMontage 能力融入，不照搬。
4. 短期不做大规模技术重构。
5. 生产模板是产品化主入口。

### 12.2 待确认问题

1. 生成页是否默认只展示当前生产线，还是同时展示 2-4 个生成方式卡片。
2. 项目设置入口放在现有 Streamlit 设置区，还是先做生成页内的轻量设置。
3. 真实素材混剪第一版是否只支持用户上传素材。
4. 高质量解释视频第一版优先试 HyperFrames 还是 Remotion。
5. 是否需要为“选题直出”单独定义一个日常短视频模板入口。

建议默认决策：

1. 生成页默认展示当前生产线，同时提供“更换生产线”。
2. 项目默认设置先放在生成页内，后续再移到完整项目设置。
3. 真实素材混剪第一版只支持用户上传素材。
4. 高质量解释视频第一版只选择一个 runtime 试点。
5. 为“选题直出”保留日常短视频模板入口，避免默认生成页和模板体系脱节。
