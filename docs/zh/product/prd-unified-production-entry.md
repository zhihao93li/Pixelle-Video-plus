# PRD：统一生产入口与人工确认

## 文档状态

- 状态：实施中
- 版本：v1.1
- 适用范围：React 控制台、Codex/Claude 等 Agent、工作台、任务详情、作品库
- 产品原则：发起归发起，监控归监控；人工确认是路线中的站点，不是第二次发起

## 一、结论

Pixelle 只允许从两类入口发起新的生产：

1. 用户在 React 控制台的「快速生产」中发起。
2. 用户通过 Codex、Claude 等 Agent 发起。

所有生产都必须在第一次提交时确定完整路线、最终产物和模板。路线中可以包含写稿、分镜、人工确认、图片生成、配音与合成，但这些都是同一条生产任务的连续站点。

```text
快速生产 ─┐
          ├→ 生产任务 → 工作台监控/人工确认 → 作品库
Agent ────┘        └→ 任务详情
```

工作台不再录入内容或发起生产。它是生产 Dashboard，只负责汇总已有任务，并回答：是否需要用户处理、是否正在运行、是否失败、是否已经产出。

## 二、背景与根因

当前产品同时存在以下行为：

- 工作台可以添加选题、现成文案和素材。
- 工作台可以只保存选题，也可以开始起草。
- 快速生产可以直接输入文案或素材并制作。
- 内容确认后，还可以在内容详情再次选择模板并「开始出片」。
- Agent 的「添加选题」「起草」「生产」是三段独立动作。
- 工作台和独立任务导航都在展示生产状态。

根因不是入口名称不清楚，而是产品没有明确区分“发起生产”和“处理已有生产”。一条从主题开始的路线被拆成多次发起，工作台也同时承担了内容池、入口和监控三种职责。

本 PRD 通过以下方式解决：

- React 只从快速生产发起。
- Agent 只在用户明确决定制作后发起。
- 一次发起建立完整路线。
- 人工确认可以在 React 或 Agent 对话中完成。
- 工作台只监控和处理已有任务。

## 三、产品目标

### 3.1 目标

- 用户明确知道：控制台开始新生产只去快速生产。
- 用户在 Agent 对话中也能发起并完成需要的人工确认。
- 工作台成为纯粹的生产监控与待办处理中心。
- 主题、文案和素材路线在第一次提交时确定最终产物和模板。
- 人工确认后原任务继续，不出现第二次「开始出片」。
- React 与 Agent 发起的任务进入同一套工作台、详情和作品库。
- 批量提交只产生多条独立任务，不产生额外的批次状态体系。
- 原样重试和修改后重新制作具有不同、稳定的产品语义。

### 3.2 非目标

- 本期不建设内容库、素材库、选题库或灵感库。
- 本期不提供「仅入池」或长期选题管理。
- 本期不承诺「一稿三出」。不同媒介需要适合自己的稿件和确认过程。
- 本期不提供“一次勾选视频、图集、长文并同时生产”的组合入口。
- 本期不让 Agent 自行代替用户确认。
- 本期不把工作台和作品库合并。

## 四、核心产品规则

### 4.1 新生产只有两个入口

React 中只有快速生产可以创建新的生产。Agent 只有在用户明确表达开始制作后才能创建新的生产。

以下页面不能直接创建新生产：

- 工作台
- 内容/审核详情
- 任务详情
- 作品库
- 项目设置
- 模板设置

这些页面可以跳转快速生产并预填已有内容，但最终提交必须发生在快速生产中。

### 4.2 一次发起确定完整路线

第一次提交必须确定：

- 输入类型：主题、完整文案或素材。
- 最终产物：视频、图集或长文。
- 制作方式和模板。
- 本次设置。
- 该路线中需要经过的人工确认站。

确认、打回、重写和继续执行都属于原生产任务，不创建第二条任务。

### 4.3 一题多做，不是一稿三出

同一个主题可以分别发起视频、图文和长文生产，但三种媒介需要各自适配的稿件：

```text
同一主题
├→ 视频文案 → 视频分镜 → 视频
├→ 图文文案 → 分页结果 → 图集
└→ 长文稿件 → 长文
```

视频文案的确认不能自动批准图文文案或长文稿件。用户需要复用主题时，可以复制主题重新发起；本期不为复制一句主题建设内容库。

后续可以增加「使用这个主题再次制作」快捷方式。它只负责跳转快速生产并预填主题，不改变入口边界，也不建立跨媒介稿件关系。

### 4.4 人工确认与渠道无关

真正的规则是“必须由人确认”，不是“必须在 React 确认”。

用户可以：

- 在工作台进入审核详情确认。
- 在 Codex、Claude 等支持用户明确授权的 Agent 对话中确认。

两个渠道操作同一个待确认事项。任意一边确认、修改或重新生成后，另一边必须同步最新状态。

Agent 只能提交待确认内容并转交用户的明确决定，不能根据上下文推断用户已经同意。

### 4.5 重试与重新制作分开

- 输入、模板和设置不变，只重新执行失败步骤：原样重试，可以在工作台或任务详情操作。
- 修改主题、稿件、素材、模板或设置后再次生产：重新制作，必须回到快速生产或由 Agent 发起新任务。
- 旧任务、旧错误和旧产物继续保留。

## 五、正式生产路线与确认站

第一期正式路线按以下产品合同执行：

| 路线 | 输入 | 中间内容 | 人工确认站 | 最终产物 |
| --- | --- | --- | --- | --- |
| 主题生成视频 | 主题 | 视频文案、视频分镜 | 先确认视频文案，再确认视频分镜 | 视频 |
| 文案生成视频 | 完整文案 | 视频分镜 | 确认视频分镜 | 视频 |
| 主题生成图文 | 主题 | 图文文案、分页结果 | 确认图文文案与分页结果 | 图集 |
| 文案生成图文 | 完整文案 | 分页结果 | 确认分页结果 | 图集 |
| 主题生成长文 | 主题 | 长文稿件 | 不设中间确认，生成后直接成为待检查产物 | 长文 |
| 文案生成长文 | 文案或写作材料 | 长文稿件 | 不设中间确认，生成后直接成为待检查产物 | 长文 |
| 素材生成视频 | 图片或视频素材、制作目标 | 视频分镜或编排结果 | 模板声明需要时确认分镜 | 视频 |
| 图片生成动态视频 | 图片、运动要求 | 动态视频 | 不设中间确认 | 视频 |
| 动作迁移 | 参考动作、目标角色 | 动作迁移视频 | 不设中间确认 | 视频 |
| 数字人口播 | 角色、文案或商品素材 | 数字人视频 | 文案由系统生成时确认文案；用户提供完整文案时不重复确认 | 视频 |
| Agent 配图视频 | 主题或文案、Agent 分镜 | 分镜和图片提示词、配图 | 确认完整分镜和图片提示词 | 视频 |

长文不设中间确认，是因为长文稿件本身就是最终产物；「已产出」不等于「已发布」，用户仍需在作品库检查后发布。

新增路线时必须在产品合同中明确输入、中间内容、确认站和最终产物，不能由页面临时决定是否确认。

## 六、快速生产

### 6.1 页面职责

快速生产是 React 唯一的新生产入口，负责：

1. 选择生产路线。
2. 提供该路线真正需要的输入。
3. 选择模板。
4. 调整本次设置。
5. 确认并提交生产。

### 6.2 路线选择

用户先选择最终要获得的内容，而不是先进入一个通用内容表单。

示例：

- 主题生成口播视频
- 文案生成口播视频
- 主题生成图文
- 文案生成图文
- 主题生成长文
- 文案生成长文
- 素材生成视频
- 图片生成动态视频
- 动作迁移
- 数字人口播

Agent 专用路线可以展示用途、模板和设置入口，但不能出现 React 发起按钮。

### 6.3 提交前摘要

提交前必须展示：

- 最终产物。
- 生产路线与模板。
- 本次输入摘要。
- 本次修改过的设置。
- 将经过哪些人工确认站。

提交后直接跳转工作台对应卡片或任务详情。

### 6.4 不提供内容暂存

快速生产不提供「保存选题」「仅入池」或内容草稿管理。未提交的当前输入可以作为页面临时草稿保留，但不成为 Pixelle 的正式内容，也不出现在工作台。

## 七、Agent 发起与继续生产

### 7.1 讨论阶段不写入 Pixelle

用户可以在 Codex 或 Claude 中讨论选题、文案、角度和分镜。只有用户明确表达“开始制作”“提交到 Pixelle”或同等意图后，Agent 才能发起生产。

### 7.2 Agent 发起时一次性声明路线

Agent 发起新生产时必须明确：

- 项目。
- 生产路线。
- 模板。
- 输入。
- 本次设置。
- 用户明确要求开始制作的事实。

### 7.3 Agent 动作面调整

Agent 的正式产品动作收敛为：

1. 查看实时能力。
2. 发起一条完整生产。
3. 为已有任务提交 Agent 负责的中间结果，例如分镜或图片。
4. 读取工作台、任务和产物状态。
5. 转交用户的明确确认结果。
6. 登记发布证据和指标。

以下旧动作不再作为正式生产的标准入口：

- 单独把选题加入 Pixelle。
- 先建立选题，再单独发起起草。
- 确认后再单独调用一次生产来创建第二条任务。

### 7.4 Agent 中确认

Agent 必须先展示完整待确认内容和清晰版本标识，再请求用户确认。

推荐提示：

> 分镜方案 v3，共 7 镜。请明确回复“确认这版分镜”，或者告诉我需要修改的镜头。

可以接受明确表达：

- 确认这版分镜。
- 确认 v3。
- 这版可以，确认。

不能把以下模糊表达直接视为确认：

- 还行。
- 看起来不错。
- 应该可以吧。

遇到模糊表达，Agent 必须再次询问是否正式确认。

确认成功后，Agent 明确返回确认对象和后续动作：

> 已确认分镜 v3，原任务将继续生成图片。

如果 Agent 客户端不能证明确认来自用户，则该客户端不能提交确认，只能引导用户到工作台完成。

### 7.5 Agent 中断与接手

任务不能永久绑定某一次 Agent 对话。

- 原 Agent 在线时，修改或重写结果默认返回原对话，同时同步工作台。
- 原对话关闭时，用户仍可在工作台处理。
- 另一个获得授权的 Agent 可以根据任务身份接手后续步骤。
- 工作台必须明确显示当前是在等待用户、系统还是 Agent。

## 八、人工确认、修改与重做

### 8.1 待确认页面的操作

待确认页面统一提供与当前内容匹配的操作：

- 直接编辑。
- 让系统重写。
- 重新生成选中的镜头或分页。
- 整套重新生成。
- 确认当前版本。

不要把所有非确认操作统一命名为「打回」；页面主概念应为「修改」或「重新生成」。

### 8.2 修改意见

修改意见不强制填写。

- 直接编辑不需要理由。
- 重新生成选中项不需要理由。
- 整套重新生成不需要理由。
- 用户需要控制修改方向时，可以选填意见。

没有填写意见时，系统按照当前路线和模板重新生成，不伪造用户意图。

### 8.3 状态同步

- React 发起的修改结果回到 React 待确认，同时 Agent 可读取最新状态。
- Agent 发起的修改结果回到 Agent，同时工作台同步。
- 任意一边确认后，另一边立即变成已确认。
- 任意一边修改后，旧确认立即失效，其他渠道不得继续使用旧版本确认。
- 所有修改、重新生成和确认继续使用原生产任务。

## 九、工作台与任务详情

### 9.1 工作台职责

工作台只展示已有生产任务，并按确定状态分栏：

- 待你处理
- 进行中
- 异常
- 已产出
- 已取消（通过筛选查看）

每张卡片只展示当前唯一下一步，例如：

- 审核视频文案。
- 确认分镜。
- 等待 Agent 上传图片。
- 查看失败原因。
- 原样重试。
- 查看产物。

### 9.2 从工作台删除的能力

- 删除「添加内容」。
- 删除选题、现成文案和素材录入。
- 删除「仅入池」。
- 删除从工作台选择新路线或模板。
- 删除从工作台创建新生产。

工作台空状态可以提供「去快速生产」，但只能跳转，不能原地打开生产表单。

### 9.3 删除独立任务导航

顶部导航删除「任务」。

正式主导航收敛为：

```text
工作台 / 快速生产 / 作品库 / 设置
```

任务详情继续保留，用户从工作台卡片进入，用于查看执行步骤、失败原因、取消和原样重试。

## 十、内容审核详情

内容审核详情是当前生产任务的人工处理页面，不是新生产入口。

保留：

- 查看和编辑当前待确认的文案、分镜或分页。
- 确认、系统重写、选中项重做和整套重做。
- 查看当前路线、任务状态和下一步。
- 前往任务详情或作品库。

移除：

- 确认完成后再次选择生产模板。
- 「开始出片」。
- 从当前内容直接创建另一条生产路线。

确认后明确显示：

> 已确认，原生产任务将继续执行。

如果下一步需要 Agent，明确显示：

> 已确认分镜，等待 Agent 补齐 4 张配图。

## 十一、批量生产

批量生产属于快速生产的一种填写和提交方式，不是第三种入口，也不建立批次生命周期。

一次提交十条内容时：

- 创建十条独立生产任务。
- 工作台显示十张独立任务卡。
- 每条任务独立运行、确认、失败、取消、重试和产出。
- 不展示批次卡片。
- 不计算批次总状态。
- 不提供「重试整个批次」。

提交完成后可以临时提示「成功创建 10 条任务」，但该提示不是持久化状态。

## 十二、作品库与重新制作

作品库只管理已经产出的内容。

作品库提供「基于此作品再次制作」：

1. 跳转快速生产。
2. 默认带入上一次生产实际使用的最终稿件。
3. 默认带入原生产路线、模板和本次设置。
4. 用户可以修改后发起新的生产任务。
5. 旧任务和旧作品继续保留。

如果用户改成另一种内容形式，上一次最终稿件只作为参考输入。新路线仍按自己的媒介规则重新加工，并经过该路线要求的确认站。

作品库不能直接创建新生产。

## 十三、页面职责总表

| 页面 | 唯一职责 | 可以做 | 不可以做 |
| --- | --- | --- | --- |
| 快速生产 | React 唯一生产入口 | 选路线、输入内容、选模板、改本次设置、提交单条或多条任务 | 监控全部历史任务、长期保存选题 |
| 工作台 | 生产 Dashboard | 确认、修改、查看状态、查看失败、原样重试、打开产物 | 添加内容、仅入池、选择新路线、发起新生产 |
| 审核详情 | 处理当前确认站 | 编辑、系统重写、局部重做、整套重做、确认 | 选择另一条路线、再次开始出片 |
| 任务详情 | 执行与故障详情 | 查看步骤、取消、原样重试 | 修改内容后创建新版本 |
| 作品库 | 产物管理 | 预览、发布、记录证据、跳转快速生产再次制作 | 直接创建新生产 |
| 设置 | 长期默认配置 | 管理项目、模板、模型、声音、画面和发布设置 | 发起生产 |

## 十四、验收条件

### 14.1 生产入口

- [ ] React 中只有快速生产可以提交新的生产任务。
- [ ] 工作台不存在「添加内容」「仅入池」或内容录入表单。
- [ ] 审核详情不存在模板选择和「开始出片」。
- [ ] 任务详情、作品库和设置不能直接创建新生产。
- [ ] Agent 可以发起实时能力允许的完整生产路线。
- [ ] Agent 在用户未明确决定制作前，不向 Pixelle 创建内容或任务。
- [ ] 所有正式产物都能追溯到唯一生产任务。

### 14.2 路线完整性

- [ ] 主题生成视频第一次提交时已经确定视频模板和最终产物。
- [ ] 主题生成视频依次经过视频文案确认和视频分镜确认。
- [ ] 文案生成视频不重复确认用户提供的完整文案，但必须确认新生成的分镜。
- [ ] 主题生成图文确认图文文案和分页结果。
- [ ] 文案生成图文确认分页结果。
- [ ] 主题或文案生成长文不产生中间确认任务，完成后直接进入已产出。
- [ ] 长文已产出后仍需用户检查才能发布。
- [ ] Agent 配图视频确认分镜和图片提示词后，原任务继续等待图片和合成。
- [ ] 任一路线确认后都不会再次要求用户选择模板或开始出片。

### 14.3 React 与 Agent 确认

- [ ] 同一个待确认事项可以在 React 或受支持的 Agent 对话中完成。
- [ ] React 确认后，Agent 读取到已确认状态且不能重复确认。
- [ ] Agent 中确认后，工作台立即移出「待你处理」或显示下一个待办。
- [ ] Agent 展示完整待确认内容和明确版本后才能请求确认。
- [ ] 用户明确回复「确认这版」可以完成确认，无需再回 React 点击。
- [ ] 「还行」「看起来不错」等模糊表达不会被当作正式确认。
- [ ] Agent 不能在没有用户明确确认的情况下自行批准。
- [ ] Agent 客户端无法证明用户授权时，确认请求明确失败并引导用户去工作台。
- [ ] 确认后内容发生修改，旧确认立即失效。

### 14.4 修改与重新生成

- [ ] 用户可以直接编辑待确认文案、分镜或分页。
- [ ] 用户可以让系统重写当前内容。
- [ ] 用户可以只重新生成选中的镜头或分页。
- [ ] 用户可以整套重新生成。
- [ ] 修改意见全部为选填，不填写也能执行。
- [ ] 局部重做不会改变未选中的镜头或分页。
- [ ] 修改或重做后仍使用原生产任务，不创建第二条生产任务。
- [ ] React 发起的修改和 Agent 发起的修改在两个渠道显示同一最新版本。
- [ ] 原 Agent 对话关闭后，任务仍可在工作台处理或被另一个授权 Agent 接手。

### 14.5 工作台和导航

- [ ] 主导航只有工作台、快速生产、作品库和设置。
- [ ] 独立任务导航已经删除。
- [ ] 工作台卡片可以进入任务详情。
- [ ] 工作台只按待你处理、进行中、异常、已产出和已取消展示确定状态。
- [ ] 每张任务卡只突出当前唯一下一步。
- [ ] 等待 Agent 时明确显示等待 Agent 以及尚缺的内容。
- [ ] 工作台空状态只提供跳转快速生产，不原地创建任务。

### 14.6 批量生产

- [ ] 批量入口只存在于快速生产。
- [ ] 一次提交十条内容会建立十条独立生产任务。
- [ ] 工作台展示十张任务卡，不展示批次卡。
- [ ] 不存在批次总状态、批次失败状态或批次重试按钮。
- [ ] 其中一条失败不会改变其他九条的状态或操作。
- [ ] 用户只能重试具体失败任务。

### 14.7 重试与重新制作

- [ ] 原输入、模板和设置不变的失败任务可以从工作台或任务详情原样重试。
- [ ] 原样重试保留在同一生产任务下，并保留旧失败记录。
- [ ] 修改主题、稿件、素材、模板或设置后只能从快速生产或 Agent 发起新任务。
- [ ] 作品库提供「基于此作品再次制作」。
- [ ] 该操作跳转快速生产并预填上一次实际使用的最终稿件、路线、模板和设置。
- [ ] 新任务不会覆盖旧任务和旧作品。
- [ ] 改成另一种媒介时，新路线仍执行自己的内容加工和确认规则。

### 14.8 Agent 动作面

- [ ] Agent 发起生产时一次性明确项目、路线、模板、输入和本次设置。
- [ ] 「添加选题」和「单独起草」不再是正式生产的标准动作。
- [ ] 提交分镜和上传图片只能继续已有生产任务。
- [ ] 确认后 Agent 不会再调用第二次生产创建重复任务。
- [ ] Agent 可以按任务身份读取状态并继续自己的后续步骤。
- [ ] 另一个授权 Agent 可以接手未完成的 Agent 步骤。
- [ ] React 与 Agent 发起的任务在工作台使用相同状态和操作语义。

### 14.9 用户理解

不阅读帮助文档的用户应能回答：

1. 在控制台哪里开始新生产？——快速生产。
2. 在哪里查看所有生产是否正常？——工作台。
3. 在哪里处理文案或分镜确认？——工作台，或当前 Agent 对话。
4. 在哪里查看详细执行和失败原因？——从工作台进入任务详情。
5. 在哪里管理已经生成的内容？——作品库。
6. 想修改后重新制作怎么办？——进入快速生产发起新任务。

## 十五、实施顺序

1. 建立路线级生产任务与确认站合同，覆盖本 PRD 的正式路线表。
2. 将快速生产改为 React 唯一生产入口。
3. 改造 Agent 动作面，使其一次发起完整路线并继续原任务。
4. 建立 React 与 Agent 共用的待确认事项及状态同步。
5. 支持直接编辑、系统重写、局部重做和整套重做。
6. 移除工作台的添加内容、仅入池和生产发起能力。
7. 移除审核详情的二次选模板和开始出片。
8. 删除独立任务导航，将任务详情收口到工作台卡片。
9. 将批量提交改为完全独立的任务卡，不保留批次状态。
10. 将作品库再次制作改为跳转快速生产并预填最终稿件。
11. 按第十四章逐项完成产品验收。
