# PRD：统一生产设置体验

## 文档状态

- 状态：v1.2 快速生产默认折叠整改已实现并通过前端验收；真实生成链路仍按本文件端到端验收项继续验证
- 版本：v1.2
- 日期：2026-07-15
- 适用范围：React 控制台中的「设置 → 模板」与「快速生产」
- 关联能力：模板长期默认、本次覆盖、AI 步骤设置、资源选择、提交前摘要
- 不改变：Pipeline 路线、模板数据合同、Provider 调用方式、人工确认规则
- 视觉规范：[`apps/console/DESIGN.md`](../../../apps/console/DESIGN.md)

## 一、结论

Pixelle 只保留一套生产设置合同，但提供两种符合不同任务目的的编辑体验：

| 场景        | 用户目的                       | 保存结果           | 页面形态                                     |
| ----------- | ------------------------------ | ------------------ | -------------------------------------------- |
| 设置 → 模板 | 把一套制作方法整理成长期默认   | 保存到当前模板     | 完整、分阶段的设置页                         |
| 快速生产    | 为正在制作的这一条内容临时微调 | 只进入当前生产任务 | 内容始终可见，设置默认收起，按需展开完整步骤 |

可以把模板理解为餐厅的长期菜谱，把本次设置理解为顾客这一单的备注：

- 修改菜谱会影响以后使用该模板的新任务。
- “少一点背景音乐”“这次换个声音”只影响当前这一单。
- 两边使用同一批真实原料和同一套制作参数，不能各做一套名字相似、实际含义不同的设置。

本 PRD 的核心不是减少配置项，而是让用户在正确的时间看到正确的层级：

```text
模板页：完整查看和整理长期默认

快速生产：输入内容
          ↓
        本次设置摘要（默认收起）
          ↓ 需要时展开
        按生产步骤调整
          ↓
        提交生产任务
```

## 二、背景与根因

### 2.1 当前问题

现有产品虽然已经复用了部分设置组件，但用户体验仍存在以下问题：

1. 快速生产把「内容」和「本次设置」做成互相切换的两个工作区。用户查看设置时看不到正在制作的内容，修改设置后也难以立即理解它对当前内容的影响。
2. 模板设置和本次设置虽然指向相近参数，但页面组织、入口、说明和操作方式不统一，用户会误以为是两套系统。
3. 模板页一次展示大量字段，却没有先解释这条生产路线经过哪些阶段、每个阶段负责什么。
4. 快速生产把一部分“常用设置”直接铺在首屏，虽然减少一次点击，却让设置看起来像提交前必须检查的表单，挤压了输入内容这个核心任务。
5. 设置来源不够清楚。用户难以区分出厂默认、模板默认和本次覆盖，也不知道自己改动后会影响哪里。
6. 部分资源选择曾经用静态品牌或模型分类代替真实 Provider，容易出现“设置里已经配置，但生产页看不到”的假能力。
7. AI 步骤中的模型、Provider、提示词模板和提示词正文虽然属于同一操作，却曾被拆成含义不清的“手册”、文本语法或孤立输入框。
8. 分镜数量曾被当成普通数字配置暴露给用户，但当前产品规则是由分镜模型依据内容决定，不应要求用户在生产前手填。
9. 常用设置曾被从原生产阶段抽出来集中展示，展开完整设置后，同一阶段的一部分留在外面、另一部分出现在下面。例如配音相关字段被用户感知为两个设置区。
10. 即使把常用项放回所属阶段，只要首屏仍铺开多个设置阶段，快速生产就会退化为缩小版模板页；它既不够快，也不如完整设置清晰。
11. 一些 Ghost 动作、只读 Badge、说明文字和普通文本链接静态外观过于接近，用户需要尝试点击才能判断什么可以操作。

### 2.2 根因

根因不是字段太多，而是三个产品层级混在了一起：

- **能力合同**：这条 Pipeline 到底支持哪些设置。
- **长期默认**：当前模板为以后任务保存了什么。
- **单次决定**：当前任务临时覆盖了什么。

过去页面各自判断“应该展示什么”，导致相同能力出现不同交互，甚至出现页面自行补字段、写死资源列表或按模板 ID 特殊处理的倾向。

本 PRD 要把三层关系固定为：

```text
Pipeline 声明可用能力
        ↓
模板保存长期默认
        ↓
快速生产只提交本次真正修改的覆盖项
```

## 三、产品目标

### 3.1 目标

- 用户第一次进入模板页，就能理解完整生产路线和每个阶段的作用。
- 用户在快速生产中不离开内容上下文即可按生产步骤完成本次微调。
- 快速生产不牺牲完整能力；需要时仍可找到当前 Pipeline 允许的全部本次设置。
- 模板页与快速生产复用同一套字段、控件、资源、分组和术语。
- 每个设置都明确展示当前来源和影响范围。
- 用户提交前能看到本次究竟覆盖了哪些设置，以及路线中需要哪些人工确认。
- 新增 Pipeline 或设置字段时，通过共享合同自然进入两个页面，不再按页面或模板 ID增加特殊分支。
- 所有 Provider、模型、工作流、音色、模板和音乐选项都来自真实设置与资源接口。
- 保留当前 React 控制台的克制、清晰、低装饰 UI 风格。

### 3.2 成功标准

- 新用户不阅读帮助文档，也能回答“我现在改的是长期模板还是当前这一条”。
- 快速生产默认不展示任何设置控件，常规任务可以直接提交。
- 专业用户可以在同一页面找到 Pipeline 允许的全部本次设置。
- 模板页和快速生产对同一个参数使用相同名称、相同控件和相同取值。
- 页面展示的 Provider 与系统真实配置完全一致，不出现静态品牌列表或根据模型名称猜测 Provider。
- 本次设置 payload 只包含用户实际修改的字段。

## 四、非目标

- 不新增 Pipeline，不改变现有 Pipeline 的输入、步骤或最终产物。
- 不把模板变成可以任意增删生产步骤的流程编辑器。
- 不建设模型自动选择、自动推荐或后台静默切换。
- 不为了页面更简单而删除 Pipeline 已经允许用户调整的配置。
- 不把所有参数都强行放入快速生产首屏。
- 不建设第二套“快速设置”数据结构。
- 不在本期建设复杂的配置版本审批、团队权限或多人协作。
- 不允许快速生产直接覆盖当前模板。
- 不把 Demo 中的静态示例值当成生产事实源。

## 五、核心产品模型

### 5.1 三层设置来源

同一个设置的最终值按以下顺序确定：

```text
项目默认 → 模板生效默认 → 本次覆盖
```

页面需要同时表达两件事：

1. 当前值来自哪里。
2. 用户是否在当前页面产生了尚未保存或提交的修改。

推荐状态文案：

| 页面     | 未修改时            | 修改后   |
| -------- | ------------------- | -------- |
| 模板设置 | 出厂默认 / 已自定义 | 未保存   |
| 快速生产 | 模板默认            | 本次修改 |

“未保存”与“值来自哪里”不是同一个概念，代码和 UI 不得混为一个状态。

### 5.2 两种页面，不是两套能力

两处页面必须共享：

- 字段定义。
- 产品名称与说明。
- 控件类型。
- 枚举、范围和校验。
- Provider 与模型资源。
- 提示词选择和正文编辑。
- Pipeline 阶段顺序与设置分组。
- 预览能力。
- 设置值与提交参数之间的唯一适配器。

两处页面只允许在以下方面不同：

- 展示密度。
- 默认展开程度。
- 保存范围。
- 页面主操作。
- 当前模式依法允许编辑的字段集合。

### 5.3 字段集合的事实来源

模板页与快速生产的字段集合不完全相同，不能为了视觉统一强行补齐：

- 模板页只展示当前模板允许保存为长期默认的字段，即模板生成配置返回的 `overridable_keys`。
- 快速生产只展示当前模板允许作为单次覆盖提交的字段，即 `allowed_user_params`。
- 字段还必须属于当前 Pipeline 的阶段设置合同，或已经在共享字段注册表中明确登记。
- 只读产品策略必须明确展示。例如合成引擎可以在快速生产中显示，但不能伪装成可编辑。
- 未登记字段不得静默消失；应在“更多参数”中只读显示，提醒开发者补全正式登记。
- 页面不得“好心”添加合同中不存在的字段。

当前「图文口播视频 / 标准基础版」在 Demo 中作为示例：模板页与快速生产的字段数量、范围可以不同，这是权限事实，不是体验不一致。

### 5.4 快速生产默认不展示设置控件

快速生产的首要任务是提供输入并发起生产，而不是逐项检查配置。页面默认只显示当前模板、本次覆盖摘要和“展开本次设置”，不展示画面模板、音色、语速、背景音乐或其他设置控件。

规则：

- 收起时不渲染任何可编辑设置字段，也不根据 Pipeline、模板或所谓“常用程度”猜测首屏字段。
- 展开后一次展示当前 Pipeline 允许的完整本次设置，并严格按真实生产阶段分组。
- 每个字段只存在于一个所属阶段，不建立“常用设置”和“完整设置”两份实例。
- 收起只改变可见性，不清空已经修改的值；摘要持续显示覆盖数量与字段名称。
- 模板名称、来源和覆盖摘要始终可见，因此用户无需展开就能判断这次是否沿用默认。
- 现有 `quick_setting_keys` 不再决定快速生产首屏结构；若后端仍为兼容保留该字段，前端不得据此重新铺开设置控件。

## 六、信息架构

### 6.1 设置 → 模板

模板页负责“整理一套以后反复使用的制作方法”。

页面顺序：

1. 模板身份与用途。
2. 生产路线图。
3. 每个阶段当前摘要。
4. 分阶段完整设置。
5. 本次修改清单。
6. 保存模板。

页面可以一次展开多个阶段，不能强迫用户像向导一样逐步前进。路线图用于定位和理解，不是流程门槛。

### 6.2 快速生产

快速生产负责“用选定路线完成当前这一条内容”。

页面顺序：

1. 当前生产方式与模板。
2. 当前路线真正需要的输入。
3. 本次设置摘要。
4. 按需展开的分阶段本次设置。
5. 提交前摘要与开始制作。

内容输入必须始终可见。打开设置时不得用另一个页面或标签把内容完全替换掉。

### 6.3 结果与模板沉淀

快速生产中的修改默认只影响当前任务。

当任务成功产出后，可以在任务结果或作品详情提供“保存为新模板”：

- 使用原模板作为基础。
- 带入这次真正提交的覆盖项。
- 要求填写新模板名称。
- 不覆盖原模板。
- 不在生产提交前用该操作干扰主流程。

该能力可作为 P1；P0 必须先保证本次覆盖不会误写长期模板。

## 七、模板设置页详细交互

### 7.1 页面头部

必须展示：

- 模板名称。
- 对应生产方式。
- 最终产物。
- 模板用途说明。
- 当前使用项目数。
- 开始制作入口。
- 克隆、重命名和停用等管理操作。

文案必须明确：这里修改的是长期默认；开始制作后仍可为当次内容单独调整。

### 7.2 生产路线图

路线图按 Pipeline 的真实阶段顺序展示，例如：

```text
分镜 → 视觉提示 → 配音 → 画面 → 合成
```

每个阶段展示：

- 阶段名称。
- 一句职责说明。
- 当前关键设置摘要。
- 是否存在未保存修改。

点击阶段滚动到对应设置区域。路线图不允许通过前端猜测阶段，也不能为每个模板手写一份。

### 7.3 阶段设置

每个阶段提供：

- 当前生效摘要。
- 完整字段。
- 每个字段的来源标签。
- 对复杂字段的简短说明。
- “恢复此阶段默认”。
- 与该阶段相关的真实预览操作。

首屏可以折叠高级字段，但完整字段必须可找到。

### 7.4 保存

保存前展示精确变更清单：

```text
本次将修改 3 项：
- 配音音色：云健 → 晓晓
- 语速：1.0× → 1.1×
- 背景音乐：default.mp3 → 无
```

保存按钮只在有修改时可用。保存成功后来源状态更新为“已自定义”。

离开页面前存在未保存修改时必须提醒。

## 八、快速生产详细交互

### 8.1 当前生产身份

页面头部必须同时展示：

- 生产方式名称。
- 最终产物。
- 当前模板名称。
- “管理长期模板”入口。

用户不需要返回上一级才能确认自己正在使用哪条路线。

### 8.2 内容输入

输入区域只展示当前 Pipeline 真正需要的输入。

示例：

- 文案生成视频：完整视频文案。
- 主题生成视频：主题或内容方向，并展示写稿相关设置。
- 素材生成视频：素材上传与制作目标。

不得因为多个路线最后都会生成视频，就共用一份包含无关字段的通用表单。

分镜数量规则：

- 当前由分镜 LLM 决定的路线，不展示“分镜数量”输入。
- 页面明确说明系统会根据内容转折、画面变化和节奏决定分镜数量。
- 用户需要控制分镜时，在人工确认站合并、拆分、局部重做或整套重做。
- 只有未来某条 Pipeline 明确把固定数量作为用户输入时，才可通过合同展示该字段。

### 8.3 本次设置首屏

本次设置紧跟在内容输入后，不做与内容互斥的标签页。

默认展示：

- “使用模板默认”或“已调整 N 项”的状态提示。
- 当前模板名称。
- 当前覆盖摘要；存在覆盖时列出字段名称。
- “管理长期模板”。
- “展开本次设置”。
- 存在覆盖时显示“恢复模板默认”。

默认状态不显示任何设置控件或生产阶段卡片。用户无需检查设置即可直接提交；只有明确想调整这一条任务时才展开。

### 8.4 展开本次设置

展开后：

- 仍留在当前快速生产页面。
- 内容输入和提交区不丢失。
- 按与模板页相同的 Pipeline 阶段分组。
- 字段名称、控件和资源与模板页一致。
- 从第一阶段到最后阶段按 Pipeline 顺序展示，不拆出独立“常用设置区”。
- 每项设置只渲染一次；音色、语速等配音字段全部归入配音阶段，背景音乐字段全部归入合成阶段。
- 阶段导航标记哪些阶段存在本次覆盖。
- 可以恢复单个字段、单个阶段或全部模板默认。

收起后保留已修改值，并在摘要中显示具体改动数量。

### 8.5 提交前摘要

开始制作前必须展示：

- 生产方式。
- 最终产物。
- 当前模板。
- 输入摘要。
- 分镜策略。
- 需要经过的人工确认站。
- 本次覆盖数量与字段名称。

没有本次覆盖时显示“全部沿用模板默认”。

提交 payload 只包含实际修改的字段，未修改字段由后端按项目与模板默认合并。

### 8.6 提交后

- 创建正式生产任务。
- 进入工作台或任务详情。
- 本次覆盖固化到该生产任务，之后模板变化不能反向改变已经提交的任务。
- 路线到达人工确认站时进入“待你处理”，而不是再次要求用户发起生产。

## 九、统一 AI 步骤设置

本 PRD 继续遵守《统一 AI 步骤设置与提示词库》的合同。

每个可配置 AI 步骤统一展示：

```text
模型
[真实 LLM 服务 ▼] [搜索或选择模型 ▼]

提示词
[已有提示词 ▼] [展开编辑]
[提示词正文]
```

规则：

- Provider 列表读取设置中心已经启用和配置的真实 LLM 服务。
- 模型列表读取所选 Provider 的真实模型目录，并支持搜索。
- 不根据模型名字推测 OpenAI、DeepSeek、Qwen 等品牌归属。
- 不使用静态品牌列表伪装 Provider。
- 读取失败必须显示失败原因和重试，不得回退到假数据。
- 本次编辑提示词正文只影响当前任务。
- 模板页编辑提示词正文保存为模板覆盖。
- 存在正文覆盖时显示“自定义正文 · 不跟随提示词库”，并提供“恢复跟随模板”。
- 提示词库用于管理复用，不是编辑提示词的必经入口。

## 十、资源选择与预览

### 10.1 真实资源

以下选择项必须动态读取系统事实：

- LLM Provider 与模型。
- 图片 Provider 与模型。
- 图片与 TTS 工作流。
- 配音音色。
- 画面模板。
- 背景音乐。
- 提示词模板。

资源未配置时：

- 明确显示“未配置”或“不可用”。
- 提供前往对应设置页的入口。
- 不能把不可用资源展示成可以正常生产。

### 10.2 预览

- 模板页可在相关阶段提供画面、配音、媒体或模板预览。
- 快速生产可提供当前内容与设置的预览摘要。
- 真实预览失败时显示真实错误，不用占位图、旧缓存或假成功掩盖。
- Demo 中的图片只用于表达布局，不代表正式预览已经完成。

## 十一、状态、错误和空状态

### 11.1 资源加载

- 页面进入时并行加载模板、Pipeline 与资源目录。
- 某类资源失败时，只阻断依赖该资源的设置，不让整个页面无提示空白。
- 失败区域显示原因与“重新读取”。
- 已读取的真实数据可以保留，但必须标明其他区域读取失败。

### 11.2 模板变化

快速生产中切换模板后：

- 重新读取该模板的允许字段和生效默认。
- 清除不再合法的本次覆盖。
- 对仍合法但值不兼容的字段给出明确提示。
- 不把上一个模板的隐藏设置静默提交到新模板。

### 11.3 Provider 变化

切换 Provider 后：

- 模型选择只显示该 Provider 的真实模型。
- 当前模型不属于新 Provider 时清空并要求重新选择。
- 不能保留一个看似有值、实际不会由该 Provider 调用的模型。

### 11.4 无可调整设置

如果当前 Pipeline 没有允许用户调整的本次设置：

- 保留模板摘要。
- 显示“当前生产方式没有可调整的本次设置”。
- 不展示空白容器或无意义的“展开全部”。

## 十二、视觉与可用性要求

- 延续现有 Pixelle 的浅色背景、细边框、绿色主操作和低装饰风格。
- 不把页面做成大量独立卡片拼图；优先使用清晰分区、留白和分隔线。
- 内容输入是快速生产的视觉主区域，本次设置是紧邻的辅助区域。
- 右侧摘要在桌面端可固定；移动端下移到提交区域。
- 页面标题、阶段标题和字段标签即使快速扫读也能理解任务。
- 产品文案说明“影响范围”和“下一步”，不解释内部实现。
- 所有字段有可关联标签；键盘可以完成主要操作。
- 展开、收起和阶段跳转使用短促过渡，不做装饰性动画。
- 下拉层必须通过 Portal 或等价机制避免被父容器裁切，并支持视口碰撞处理。
- 搜索型下拉支持键盘方向键、回车选择和清晰的空结果。

### 12.1 交互语义必须可见

本页面遵守 `apps/console/DESIGN.md`，不再以“都很克制”为理由把不同对象做成相同外观：

| 对象     | 必须呈现的视觉线索                 | 本场景示例               |
| -------- | ---------------------------------- | ------------------------ |
| 主要动作 | 实心品牌色、明确动宾文案           | 开始制作、保存模板       |
| 次要动作 | 稳定边框或明确按钮轮廓             | 展开本次设置、预览       |
| 页面跳转 | 真实链接语义，并有下划线或按钮轮廓 | 管理长期模板             |
| 局部工具 | 图标与动作词组合，hover/focus 明确 | 恢复此阶段、恢复模板默认 |
| 来源标签 | 胶囊标签，无 hover、无下拉箭头     | 模板默认、本次修改       |
| 说明文字 | 次级文字色，不带按钮轮廓和手型     | 这里只调整这一条任务     |

- 用户在不移动鼠标时也能区分“可以操作”和“只是在说明”。
- Ghost Button 只用于上下文已经明确的低层级工具，不用于重要跳转或页面唯一推进动作。
- Badge 只传达来源、分类或状态，不能承担点击、筛选和展开。
- 禁用动作附近必须说明不可用原因；不能只降低透明度。
- 本期不替换 shadcn。`DESIGN.md` 定义规则，shadcn/Radix 组件负责实现规则。

## 十三、共享实现要求

### 13.1 单一组件合同

使用同一个生产设置编辑器支持两种模式：

- `recipe`：编辑长期默认。
- `run`：编辑本次覆盖。

该编辑器负责：

- 按 Pipeline 阶段组织字段。
- 使用共享字段注册表选择控件。
- 展示来源与修改状态。
- 校验值。
- 处理字段、阶段和全部恢复。
- 输出精确 dirty keys。

页面外壳负责：

- 模板页的完整路线和保存操作。
- 快速生产的内容输入、折叠摘要、提交摘要和任务提交。

### 13.2 唯一参数适配器

- UI、草稿和 API 统一使用后端合同的 snake_case 键名。
- 只保留一个 UI 值到生产参数的适配器。
- 不在模板页、快速生产页和提交函数中各维护一份映射。
- CI 中检查旧 camelCase 或重复映射没有重新出现。

### 13.3 展示元数据

共享字段注册表至少包含：

- 产品名称。
- 说明。
- 控件类型。
- 作用范围。
- 是否高级。
- 枚举或资源类型。
- 数值范围。
- 校验规则。

Pipeline 负责声明：

- 阶段及顺序。
- 每阶段允许的设置键。

历史字段 `quick_setting_keys` 不再参与快速生产首屏展示；保留期间仅视为兼容元数据，不得成为页面行为的事实来源。

模板负责声明：

- 绑定的 Pipeline。
- 长期覆盖值。
- 允许的本次覆盖范围。

页面不得复制 Pipeline、模板或资源事实。

## 十五、实施范围与优先级

### P0：统一正确性

1. 保持模板页与快速生产使用同一个生产设置编辑器和字段注册表。
2. 模板模式严格使用 `overridable_keys`；本次模式严格使用 `allowed_user_params`。
3. 删除页面按 Pipeline ID 或模板 ID 特殊决定字段的逻辑。
4. 快速生产取消“内容 / 本次设置”互斥切换，内容输入始终可见。
5. 快速生产增加模板摘要和“展开本次设置”，首屏不直接渲染设置控件。
6. 展开后直接使用当前 Pipeline 的完整分阶段设置，不建立常用项投影。
7. 每项设置始终只留在所属阶段，不生成“首屏常用区 + 下方剩余区”两套结构。
8. 完整设置按与模板页相同的阶段顺序分组。
9. 本次设置只提交 dirty keys。
10. 提交前展示本次覆盖与人工确认站。
11. 所有 Provider 与资源选择读取真实接口。
12. 移除当前路线中的手工分镜数量输入。
13. 按 `DESIGN.md` 调整本页按钮、跳转、Badge 和说明文字，使其静态外观可区分。

### P1：体验完善

1. 模板页增加路线图、阶段摘要和阶段级恢复。
2. 两页统一精确变更清单。
3. 任务产出后支持把本次覆盖保存为新模板。
4. 增加真实画面、配音与模板预览。
5. 增加资源失败的分区重试和设置跳转。
6. 完成移动端和键盘交互优化。
7. 失败任务详情增加「调整本次设置并重试」：复用快速生产的本次设置编辑器，带入上一次实际生效值；修改只作用于新执行尝试，原失败记录与原设置快照必须保留，同时继续提供「按原设置重试」。Provider 凭据或连接等全局配置问题只提供明确的设置跳转，不伪装成本次任务参数。

- [ ] 下拉选项不会被父容器裁切。
- [ ] 搜索下拉支持键盘操作。
- [ ] 所有表单控件具有明确标签、帮助文本和错误提示。
- [ ] 展开、收起、恢复和提交都有可观察反馈。
- [ ] 页面视觉延续现有 Pixelle 风格，没有无关装饰或卡片堆叠。
