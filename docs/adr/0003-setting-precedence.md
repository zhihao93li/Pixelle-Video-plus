# ADR-0003：内容空间、模板与本次设置的职责

- 状态：已采纳
- 日期：2026-07-16

## 背景

长期默认和单次调整曾由不同页面各自维护字段，导致同一 Pipeline 的模板设置与快速生产设置数量、名称和交互不一致。

## 决策

内容空间只负责内容、任务和作品的归属与筛选，不参与生产设置合并。设置生效顺序固定为：模板默认 → 本次覆盖。系统级 Provider、凭据和服务默认由系统设置单独管理。Pipeline 的阶段 `setting_keys` 决定这条路线有哪些设置；模板只能编辑其 `allowed_user_params` 与阶段设置的交集，本次设置只能提交实际修改过的允许字段。

模板页与快速生产页共用同一字段目录和编辑组件。若后端返回前端尚未识别的真实字段，界面只读展示并提示升级，不能静默丢失，也不能猜测控件或伪造能力。

## 后果

- 新设置先进入共享合同，再由两个页面自然获得，不再分别补字段。
- 内容空间不再制造一层无法可靠继承的生产默认。
- 本次覆盖保持稀疏，未修改字段继续跟随模板。
- 展示方式可以不同，但字段集合、提交值和生效语义必须一致。
