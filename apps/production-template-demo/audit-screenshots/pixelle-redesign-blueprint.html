核心判断

统一壳层、创作工作台语法与状态契约；双栏只服务需要边编辑边观察结果的场景。

01

改版北极星

要迁移的是产品调性与组件语法，不是把 Demo 结构复制到所有页面。

DESIGN DECISION

一个产品壳层，三类页面骨架

编辑型工作台采用流体分栏；列表与看板保持对象密度；设置与详情使用限宽纵向结构。三者共享导航、页头、状态与控件系统。

明确放弃

不新增一条平行 Demo 产品线

正式 ProductionStudio 保留 topic、assets、图集、长文、批量等完整能力；新视觉只替换视图与壳层，不复制一套简化业务逻辑。

02

现状 → 目标

桌面与移动端都保留任务上下文，只减少视觉噪音和布局跳转。

CURRENT · 正式生成页参数先行，主动作过深
TARGET · 选定高保真方案编辑与预览同屏
移动原则

移动端不是桌面压缩版

顶部只保留上下文与主动作一级导航固定到底部，并避让 safe area。
输入与结果改为顺序流先完成输入，再展开分镜、进度与成片。
触控目标至少 44px不依赖 hover 暴露关键操作。

03

页面改版优先级

先打通主链路，再处理对象页与专项流程。

P0 · 主链路

统一壳层与生成主流程，直接决定整站是否像同一个产品。

AppShellV2唯一侧栏、68px 上下文页头、移动底栏。
正式生成页将 Demo 视觉迁入 ProductionStudio。
创作入口减少一屏多个实心 CTA。
作品库强化成片预览与全宽媒体工作区。
工作台固定列宽横滚，移动端转阶段视图。
P1 · 联动页面

承接主链路的任务、详情、配方和设置必须同步收敛。

任务中心从一级导航降为顶栏活动入口。
内容详情统一对象页头与状态动作。
配方详情卡片堆叠改成轻量配置流。
项目详情项目上下文与设置统一。
设置用户、项目、技术诊断重新分层。
P2 · 后续收口

先继承新壳层与 token，再在后续迭代重排内容。

专项管线保留独立线性任务模型。
脚本审核去重标题并统一反馈。
模板状态保持运维定位，不抢主导航。
帮助更新为新信息架构。
Streamlit冻结新功能，保留 legacy/debug。

06

上线前架构闸门

这些不是“顺便优化”，而是避免新 UI 把旧问题包装得更漂亮。

ROOT CAUSE FIRST

先修项目作用域、状态事实源与任务恢复，再扩散视觉方案。

P0 · MUST FIX
项目作用域task、batch、history 统一携带 project_id。
内容 / 生成 / 发布状态终态由后端领域动作推进，并支持幂等。
任务恢复服务重启与 404 进入 unavailable / expired，而非永久生成中。
真实分镜预览禁止任意文案都展示固定猫图；明确预估或提供 preflight。
P1 · MAINTAINABILITY
API contractOpenAPI 生成 TS client，按 domain 拆分 generationApi。
路由 manifest统一 path、title、nav、layout、projectScoped 与 lazy load。
可访问反馈InlineAlert 使用 alert/status 与 aria-live。
验收系统补路由、项目切换、状态一致性、重启恢复与视觉回归测试。
07

完成定义

不是“页面看起来统一”，而是关键链路行为、状态与响应式都可验证。

唯一壳层

所有正式路由使用 AppShellV2，Demo 路由删除或重定向。

完整模式

文案、选题、素材、图集、长文、批量能力无回退。

一致状态

生成、任务、作品库、发布可从同一事实源恢复。

桌面 / 移动

1440 与 390 视口主任务无遮挡、溢出和关键动作缺失。

链接语义

导航支持复制地址、返回与新标签页。

视觉回归

关键页面同视口对比通过，token 与设计规范同步。
