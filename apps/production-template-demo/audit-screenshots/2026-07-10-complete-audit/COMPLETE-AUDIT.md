# Pixelle 全量 UI/UX、交互与产品闭环审查

审查日期：2026-07-10  
审查范围：当前 React 前端、对应 API/持久化实现、真实本地运行页面、桌面/390px 移动端、浅色/深色主题。  
审查原则：先锁定产品与状态模型，再做视觉重构；以下范围完成前不进入大面积 UI 实现，避免同一页面做第二遍。

## 0. 结论

当前界面已经有可用的视觉基础，但还不能直接按现有信息架构做全面高保真实现。核心问题不是“少几个控件”，而是配方默认值、项目归属、任务身份、内容状态和发布记录存在互相冲突的来源。若先统一视觉，后续修正这些合同会再次改页面结构。

必须先完成 8 个 P0：

1. 设置 API 不再把真实密钥原样返回浏览器；密钥改为只写更新、后端保管、前端只拿 `configured`/掩码状态。
2. 普通生成页从模板 `effective_params` 初始化，前端只提交用户真正改过的 override。
3. 专用工作流保留精确 `template_id`，不能按模式回落到第一个内置模板；所有单条/批量提交都必须带项目。
4. 建立全局唯一、可持久化的生产尝试身份，统一 ContentItem、task、batch、history/artifact 的映射。
5. 项目范围由 API 和持久化层强制执行；项目不存在、加载失败或未选择时禁止读取/写入全局数据。
6. 生产状态机由后端原子推进，并明确重启、取消、失败、重试语义；不能依赖工作台轮询“顺便修状态”。
7. Script Review 切项目时彻底重载项目配置；步骤 2/3 的保存和提交错误必须在当前步骤可见。
8. 建立 PublishAttempt/Post 与引用完整性，区分已排期、已发布、失败；被内容或发布记录引用的资产不能无提示删除。

## 2. P0：阻止直接全面重做的根因

### P0-1 密钥被原样下发到浏览器

`GET /api/settings/config` 直接返回完整 `config.to_dict()`，React 再把 API Key、SecretId、SecretKey 等真实值放进受控输入。`type=password` 只隐藏屏幕字符，不阻止密钥出现在网络响应、浏览器内存和 DOM value 中。

目标合同：

- 读取接口只返回 `configured: boolean`、末尾标识或固定掩码，不返回原值。
- 单独的密钥更新接口采用“空值表示不修改”或显式 `clear` 动作。
- 连接测试从服务端已有密钥执行，不要求前端回传旧密钥。
- 保存普通设置时不能覆盖/清空未读取的密钥。

### P0-2 普通生成没有真正使用配方生效默认值

生成页用硬编码 standard 默认值初始化，并把这些值作为 override 提交。结果是自定义配方、素材线音量、图文线拆分方式、画幅等可能在 UI 看似选择了正确模板，实际任务却跑了另一套参数。

目标合同：

- 表单初值来自模板 `effective_params`。
- 为每个字段维护 `dirty` 状态。
- payload 只包含 dirty override；“恢复默认”删除 override，而不是写入另一套默认值。
- 提交前显示“本次生效摘要”，明确配方值与本次改动。

### P0-3 专用工作流丢失模板身份和项目归属

专用路由只携带模式，页面再寻找第一个同类内置模板；自定义 I2V/动作迁移/数字人模板可能实际执行内置模板。单条专用提交还遗漏 `projectId`，与批量路径不一致。

目标合同：

- URL 必须包含精确模板 ID，例如 `/create/generate/:templateId`，模式只用于选择渲染器。
- 所有生产请求统一包含 `project_id`、`content_item_id?`、`template_id`、`attempt_id`。
- 无项目或项目校验失败时提交按钮不可用，并显示可恢复的错误。

### P0-4 项目隔离只存在于部分 UI

当前项目为空时，部分接口会读取全局数据；内容详情可以通过 URL 打开其他/已不存在项目的数据；作品历史没有项目参数。项目加载错误还会被吞成“没有项目”。

目标合同：

- 所有内容、任务、批次、历史、作品、发布、指标接口都以项目为强制查询条件。
- 详情和 mutation 在后端核验记录属于当前项目。
- `loading / no-project / load-error / ready` 是四个不同状态，不能互相替代。
- 项目切换清空旧数据、取消旧请求，并以新项目重新加载。

### P0-5 生产身份与状态源分裂

目前同时存在 ContentItem、内存 generation task、持久 batch、history/artifact、publish record/manual metrics。真实持久化数据中已经观察到：同一内容显示 `produced`，关联批次仍是 running/pending；内容 task ID 与实际 artifact task ID 不同；关联项目已经不存在。

目标模型：

```text
Project
  └─ ContentItem
      ├─ ContentRevision
      ├─ ProductionAttempt
      │   ├─ ProductionTask(s)
      │   └─ Artifact(s)
      └─ PublishAttempt(s)
          └─ PlatformPost(s)
```

每个页面读取同一个后端状态，不在前端“推测”和回写状态。

### P0-6 后端缺少原子生产状态机

生产启动、batch 创建、ContentItem 链接和状态推进不是一个原子操作；工作台轮询历史任务后再 reconcile。服务重启会让非终态任务长期停留，重试又可能更换 batch task ID 而不更新 ContentItem 链接。

目标状态机：

```text
approved -> queued -> running -> succeeded
                         ├-> failed -> retrying -> running
                         └-> cancelled
```

- 创建 attempt、关联内容、创建任务在同一事务/原子写入中完成。
- 启动时恢复可恢复任务；不可恢复任务明确标记 interrupted。
- retry 生成新 attempt 或保留可追踪 attempt lineage，不能悄悄换 ID。
- 取消、超时和部分失败都有稳定终态。

### P0-7 Script Review 项目泄漏与错误不可见

切项目时只在字段为空时初始化起草设置，旧项目值会残留并合并到新项目。步骤 2/3 的保存/提交错误只在步骤 1 区域渲染，用户会得到“按钮没反应”的体验。

目标合同：项目变化时以新项目快照完整替换表单；错误属于具体步骤和动作，并带重试/返回编辑入口。

### P0-8 发布语义和删除引用不完整

当前手动“设为已排期/已发布”和 Buffer 接受请求混在一起，Buffer 成功只代表排期成功，不代表平台发布成功；指标又是内容级扁平字段。作品可以直接删除，未统一检查 ContentItem/PublishAttempt 引用。

目标合同：排期、平台已发布、失败分开；每个平台帖子独立记录；指标绑定 post；删除前显示引用并阻止破坏性删除或提供明确解绑/归档流程。

## 3. P1：页面与交互需要一次性纳入重构

### 3.1 全局壳层与导航

- `/demo/studio` 使用第二套壳层，应只作为设计试验页或并入正式 AppShell。
- 导航用 button 模拟链接，缺少链接语义、跳过导航和路由切换后的焦点管理。
- 未知路径回落创建页，用户无法判断 URL 错误；需 404/无权限/项目不存在页面。
- `document.title` 静态；设置 tabs 不写 URL，刷新/分享不能恢复当前页签。
- 全局完成提示固定说“视频完成”，不适用于图集、长文等 artifact。

### 3.2 创建与生成

- 创建页把所有产线平铺，主次层级弱；需要“常用/项目默认/全部能力”结构。
- 普通生成所有高级组默认展开，标准线页面过长；移动端尤其不可用。
- 结果区沿用视频文案，image_post 和 long_form 出现错误的占位和结果语言。
- long_form 缺少目标字数、写作模型、长文提示词等核心配置。
- digital human 强制本地 TTS，与配方选择冲突。
- batch 未限制 100 条、无批量取消，轮询错误不可见，结果拉取无重试。
- 完成任务/结果刷新后不能恢复；质量失败或产物缺失仍可能出现发布 CTA。
- 专用页与普通页是两套视觉和交互模型，并缺少质量、素材、发布闭环。
- 专用模式切换不更新 URL，也不清旧任务；容易把旧结果误认为当前模式结果。
- 配方页暴露过多内部字段，但缺少“为什么锁定/从哪继承/本次实际值”的清晰解释。

### 3.3 工作台、详情、任务、作品库

- 工作台空项目显示大量空框和空白，应该给出下一步动作。
- 内容详情允许非法状态回退，起草/审核部分成功后会形成半完成数据。
- “按项目节奏排期”是模拟动作，没有真实 schedule 元数据。
- 任务页同时展示 batch 行和另一套即时任务统计，已出现上方全完成、底部 0/0/0 的矛盾。
- 作品库为全局 84 项，不随当前项目；筛选、页码、选择不进 URL，刷新丢失上下文。
- 作品筛选应服务端执行，不能只在已加载的一页里筛。
- 图集/文本产物仍沿用视频型操作，缺少类型化预览、导出和发布动作。
- 加载失败时不能保留上一个项目/筛选的旧数据。

### 3.4 设置、项目与帮助

- 系统设置把健康检查、项目管理、专家开关、LLM、ComfyUI、RunningHub、Fish、资源、Buffer、COS 全塞进一个超长表单。
- 建议改为 URL-backed 二级导航：概览、项目、AI 与语音、生成引擎、发布与存储、模板、帮助。
- 设置和项目详情没有统一 dirty 状态、离开保护、保存范围与保存成功时间。
- 重置使用浏览器 `window.confirm`，缺少影响范围和不可逆说明。
- 模板状态暴露迁移/legacy 内部语言，产品用户无法形成正确心智模型。
- 被默认项目引用的模板、退役模板、自定义模板的删除/停用规则需要统一说明。
- 帮助页未渲染 Markdown/HTML，用户直接看到 `**`、`<img>`、`####`；图片也不显示。

### 3.5 移动端、主题与无障碍

- 390px 下页面标题被压成竖排，顶部主导航横向溢出，作品库/设置不可见。
- 移动端完全没有项目切换器，用户无法知道或改变当前项目。
- 项目详情的编辑按钮/字段在窄屏有裁切风险；高级生成表单过长。
- 深色主题主动作改为亮蓝，与浅色的 teal 品牌系统不一致。
- tabs、语言/平台选择部分只依赖颜色；需 `aria-selected`/`aria-pressed` 与清晰焦点。
- slider 缺少稳定的可访问名称；异步成功/失败缺少 live region。
- 需要 skip link、路由焦点、键盘操作、200% zoom、reduced motion、safe-area 验收。

## 4. 视频制作设置：完整归属模型

不再把所有参数放在一个“高级设置”里，而是按使用频率和归属分层。以下项目必须在设计与 payload 验收里逐项出现。

### 4.1 本次制作页可调整

- 输入：单条/批量、正文、标题、素材、参考视频、角色图、商品信息。
- 拆分：段落/行/句子；实际分镜预览与镜头数量。
- 画面：画幅、画面模板、模板动态参数、示例帧预览。
- 配音：TTS 引擎、音色/reference、语速、试听、必要时逐语言音色。
- 音乐：内置 BGM/上传、不使用、音量、循环/播放一次、试听。
- 合成摘要：使用的模板、合成引擎、预计时长/消耗、本次 override。
- 结果：任务阶段、失败原因、重试/取消、质量检查、产物预览、下载、进入发布。

### 4.2 配方页管理长期默认

- 拆分默认、画幅与画面模板、默认 TTS/音色/语速、BGM/音量/模式。
- workflow、provider、提示词、引擎参数等专家设置。
- 字段继承来源、固定/允许覆盖、当前生效值、恢复继承。
- 配方变更不反向修改历史任务；保存后新任务可复现。

### 4.3 产物类型专属设置

- asset_based：素材顺序、裁剪/适配、目标时长、创作意图。
- image_post：行即页/段即页、封面、页数、图集画幅；无 TTS/BGM/视频合成。
- long_form：目标字数、结构、写作模型、长文提示词、Markdown 结果；无画面/TTS/视频合成。
- I2V：图片、prompt、时长/尺寸、精确 workflow 模板。
- 动作迁移：参考视频、目标图、prompt、精确 workflow 模板。
- 数字人：角色图、文案来源、逐阶段 workflow、配音策略。
- Script Review：项目起草配置、多语言稿、人工审核、批量生产与逐语言失败恢复。

注：当前字幕样式属于画面模板合同，不应凭空增加一个与后端无对应字段的“字幕样式”控件。若产品需要独立字幕控制，先扩展模板/API 合同，再设计 UI。

## 5. 一次性实施顺序与阶段门

### Phase 0 — 合同与安全修复

范围：密钥只写、项目强隔离、精确 template ID、effective params + dirty overrides、统一 ID 字段。  
完成门：API 合同测试证明密钥不下发；跨项目读取/写入均被拒绝；每个模板 payload 快照与配方一致。

### Phase 1 — 后端生产与发布状态机

范围：ProductionAttempt/Task/Artifact/PublishAttempt/Post，原子创建，重启恢复，取消、重试、超时、删除引用。  
完成门：标准成功、失败重试、取消、重启中断、批量部分失败、发布排期/失败六条集成用例重载后状态一致。

### Phase 2 — 统一壳层与设计系统

范围：一个 AppShell、语义导航、项目上下文、URL tabs、404/错误页、标题、tokens、浅深主题、toast/dialog/sheet/form 规范。  
完成门：1440/1024/768/390 四档布局通过截图差异与键盘检查；移动端始终可切项目并访问全部主导航。

### Phase 3 — 创建与生成页面

范围：创建首页、五类普通产物、自定义配方、三类专用工作流、Script Review；统一输入、设置摘要、任务、结果框架。  
完成门：每种模板至少一条真实/受控任务贯通，payload、任务恢复、失败反馈、结果类型均有自动化断言。

### Phase 4 — 内容闭环

范围：工作台、内容详情、任务、作品库、发布、指标；全部改读统一状态模型。  
完成门：一条内容从起草到发布完整走通，任意页面刷新/切项目后身份、状态、产物、发布记录一致。

### Phase 5 — 设置、帮助与最终验收

范围：设置二级 IA、项目详情、模板/配方管理、dirty/离开保护、帮助渲染、无障碍、全量 E2E。  
完成门：核心任务键盘可完成；200% zoom、reduced motion、screen-reader smoke、移动 safe-area、错误/空态、深色主题全部验收。

## 6. 高保真设计调性
